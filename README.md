# tgBOT — Telegram-бот для опроса кандидатов

Бот ведёт диалог с кандидатом «как живой оператор»: приветствует, задаёт вопросы,
проверяет ответы, отсеивает не подходящих по условиям, показывает итоговую сводку,
отправляет карточку менеджеру и выгружает анкету **в Google Таблицу** и SQLite.

Весь сценарий — тексты, вопросы, ограничения, условия отказа — описан
в `config.yaml`. Чтобы адаптировать бота под другого заказчика или другую сферу,
код менять не нужно: достаточно заменить конфиг.

## Быстрый старт

### Linux / macOS

```bash
git clone <repo> && cd tgBOT

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python tools/configure.py              # создаст config.yaml и .env
# (или вручную: cp config.example.yaml config.yaml && cp .env.example .env)
python tools/preflight.py              # проверка: токен, менеджер, таблица, база
python -m bot
```

`preflight.py` — главный инструмент диагностики. Он проверяет токен через `getMe`,
реально отправляет тестовое сообщение менеджеру, дописывает тестовую строку
в Google Таблицу и открывает базу, а по каждой неудаче объясняет, что чинить:

```
1. Telegram API
  [ OK ] бот @AxiomAndrewbot (id 8840010912), имя в диалоге: «Андрей»
2. Чат менеджера
  [ОШИБКА] MANAGER_CHAT_ID не задан — уведомления о кандидатах отправляться не будут
       Напишите боту команду /id, он ответит числом. Впишите его в .env
```

В логе должно появиться:

```
2026-09-02 15:30:45,123 - bot - INFO - Загружен сценарий из 5 шагов: interest, full_name, age, health, crime
2026-09-02 15:30:45,456 - bot - INFO - Бот запущен!
2026-09-02 15:30:46,001 - bot - INFO - Авторизация успешна: @your_bot (id 123456789)
```

Требуется Python 3.11+.

### Windows (PowerShell)

`.env`, `config.yaml` и `credentials.json` не хранятся в репозитории, поэтому
в свежераспакованном проекте их нет — их создаёт `configure.py`:

```powershell
cd "C:\путь\до\tgBOT"

py -3 -m venv .venv
.\.venv\Scripts\Activate.ps1          # если ругается на политику выполнения:
                                       # Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
pip install -r requirements.txt

py tools\configure.py                  # спросит токен, чат менеджера и ссылку на таблицу
py tools\preflight.py                  # проверит, что всё настроено
py -m bot                              # запуск
```

`configure.py` сам найдёт JSON-ключ сервисного аккаунта в папке проекта,
в «Загрузках» или на «Рабочем столе», скопирует его в `credentials.json`
и напечатает адрес сервисного аккаунта, которому нужно открыть доступ к таблице.

Остановить бота — `Ctrl+C`.

### Команды бота

| Команда   | Что делает                                                    |
|-----------|---------------------------------------------------------------|
| `/start`  | Начать (или начать заново) опрос                              |
| `/cancel` | Прервать диалог, стереть временные данные (синоним — `/stop`)  |
| `/id`     | Показать ID чата — так узнаётся `MANAGER_CHAT_ID`              |
| `/stats`  | Сколько анкет в базе (отвечает только в чате менеджера)        |

## Конфигурация

Два файла:

| Файл | Что внутри | В git |
|------|------------|-------|
| `config.yaml` | сценарий, все тексты, ограничения, настройки | ❌ нет (`.gitignore`) |
| `.env` | токен, чат менеджера, прокси, ключи Google | ❌ нет |

**Переменные окружения имеют приоритет над YAML** — удобно для продакшна:

| Переменная | Заменяет |
|------------|----------|
| `BOT_TOKEN` | `bot.token` |
| `MANAGER_CHAT_ID` | `bot.manager_chat_id` |
| `PROXY_URL` | `bot.proxy` |
| `GOOGLE_SHEETS_ENABLED` | `google_sheets.enabled` |
| `GOOGLE_CREDENTIALS_FILE` | `google_sheets.credentials_file` |
| `GOOGLE_SPREADSHEET_ID` | `google_sheets.spreadsheet_id` |
| `GOOGLE_WORKSHEET` | `google_sheets.worksheet` |
| `CONFIG_PATH` | путь к самому конфигу |
| `LOG_LEVEL` | `logging.level` |

Конфиг проверяется при запуске: опечатка в типе шага, дубликат ключа, битый токен
или включённый Sheets без `spreadsheet_id` — бот скажет, что именно не так, и не стартует.

## Сценарий: как добавить свой вопрос

Сценарий — это список `survey` в конфиге. Шаги идут сверху вниз, каждый шаг —
одно состояние диалога. Добавили блок в YAML — появился новый вопрос.

```yaml
survey:
  - key: license                 # идентификатор: колонка в БД/таблице и {подстановка}
    type: yes_no                 # yes_no | text | number
    label: "Права кат. C"        # подпись в сводке и отчётах (null — не показывать)
    yes_value: "Есть"            # что писать в отчёт вместо «Да»
    no_value: "Нет"
    questions:                   # бот выбирает случайный вариант
      - "Есть ли у вас права категории C?"
      - "Ещё момент: права кат. C имеются?"
    reject_on: "no"              # «Нет» -> кандидат не подходит
    reject:
      - "Жаль, без категории C не получится. Спасибо за ответ!"
```

### Все параметры шага

| Параметр | Тип шага | Описание |
|----------|----------|----------|
| `key` | все | Уникальный идентификатор (латиница) |
| `type` | — | `yes_no`, `text` или `number` |
| `label` | все | Подпись в сводке/отчёте; `null` — шаг не попадает в сводку |
| `questions` | все | **Список** вариантов вопроса (выбирается случайный) |
| `invalid` | все | Варианты ответа на некорректный ввод |
| `suffix` | все | Приписка в сводке: `Возраст: 35 лет` |
| `min_length` | `text` | Минимальная длина ответа (для ФИО — 3) |
| `min`, `max` | `number` | Допустимый диапазон |
| `yes_value`, `no_value` | `yes_no` | Как записать ответ в отчёт |
| `reject_on` | `yes_no`, `number` | `yes` / `no` / `out_of_range` — когда кандидат отсеивается |
| `reject` | — | Варианты сообщения об отказе (диалог завершается) |
| `stop_on` | `yes_no` | `no` — вежливо попрощаться (кандидат не заинтересован) |

### Подстановки в текстах

В любом сообщении можно использовать `{фигурные скобки}`:

- `{bot_name}` — имя бота из `bot.name`;
- любой ключ из секции `vars` (например, `{articles}`);
- ответы, полученные на предыдущих шагах (`{full_name}`, `{age}`);
- `{step_min}` / `{step_max}` — границы текущего числового шага;
- в сводке и уведомлении — `{fields}`, `{username}`, `{user_id}`, `{datetime}`.

Неизвестная подстановка не роняет бота — она просто останется в тексте как есть.

## Google Таблица

После успешного прохождения опроса бот дописывает строку в Google Sheets.
Заголовки формируются из `label` шагов, поэтому таблица всегда соответствует сценарию:

| Дата и время | ФИО | Возраст | Здоровье | Судимости | Телеграм | User ID | Статус |
|---|---|---|---|---|---|---|---|
| 02.09.2026 15:30:45 | Иванов Иван Иванович | 35 | Нет проблем | Нет судимостей | @ivanov | 123456789 | Прошёл отбор |

### Настройка

Ключ сервисного аккаунта (JSON из Google Cloud) положите в корень проекта
как `credentials.json` — он в `.gitignore`.

**Если таблицы ещё нет** — бот создаст её сам, с заголовками и доступом для вас:

```bash
python tools/create_sheet.py --share ваша@почта.com
```

Скрипт напечатает ссылку на таблицу и готовые строки для `.env`:

```
GOOGLE_SHEETS_ENABLED=true
GOOGLE_SPREADSHEET_ID=1AbCdEf...
```

**Если таблица уже есть** — узнайте адрес сервисного аккаунта:

```bash
python tools/create_sheet.py --whoami
```

откройте таблице доступ для этого адреса (**Поделиться → Редактор**) и впишите
её id в `.env` (id — часть URL между `/d/` и `/edit`).

В обоих случаях в проекте Google Cloud должны быть включены **Google Sheets API**
и **Google Drive API** (*APIs & Services → Library*).

Проверка:

```bash
python tools/preflight.py
```

**Важно:** если Google Sheets недоступен (нет сети, кончилась квота, отозван доступ),
ошибка попадёт в лог, а диалог с кандидатом продолжится как обычно — анкета
в любом случае сохранится в SQLite и уйдёт менеджеру.

## Уведомление менеджеру

Куда слать — `MANAGER_CHAT_ID` (или `bot.manager_chat_id`). Подойдёт:

- ID пользователя: `123456789` — **напишите боту `/id`**, он ответит числом;
- ID группы: `-1001234567890` — бота нужно добавить в группу;
- канал: `@channel_name` — бот должен быть администратором.

Шаблон настраивается (`manager_notification` в конфиге):

```
🔔 Новый кандидат!

ФИО: Иванов Иван Иванович
Возраст: 35
Здоровье: Нет проблем
Судимости: Нет судимостей
Телеграм: @ivanov
ID: 123456789
Дата: 02.09.2026 15:30
```

Если отправить не удалось (`Chat not found`, бот не в группе), это пишется в лог
как `ERROR`, диалог с кандидатом не прерывается.

## Прокси

Если Telegram API недоступен напрямую:

```yaml
bot:
  proxy: "socks5://127.0.0.1:1081"      # или socks5://user:pass@host:port, http://...
```

или `PROXY_URL=socks5://127.0.0.1:1081` в `.env`. `null` / пусто — работать напрямую.
Если прокси указан, но не отвечает, бот завершится с понятным сообщением:

```
ERROR - Сетевая ошибка при подключении к Telegram: All connection attempts failed
ERROR - Проверьте, работает ли прокси socks5://127.0.0.1:1081
```

## Живое общение

Чтобы диалог не выглядел «ботским»:

- **Вариативность.** Для каждого вопроса, отказа и сообщения об ошибке в конфиге
  задан список из 3–5 формулировок, бот каждый раз выбирает случайную.
- **«Печатает...».** Перед каждым сообщением бот показывает статус `typing`
  и выдерживает паузу: случайная база + надбавка за длину текста (длинные реплики
  «печатаются» дольше).

```yaml
typing:
  enabled: true
  min_delay: 1.2
  max_delay: 2.4
  per_char: 0.012      # +0.012 сек на символ
  max_delay_cap: 5.0   # но не дольше 5 сек
```

- **Разговорные обороты** — «Ок», «Понял», «Увы», «Извините» — уже в текстах конфига.
- **Эмодзи** можно выключить целиком: `bot.emoji: false` (бот вырежет их из всех сообщений).
- **Понимание свободных ответов.** Кроме кнопок бот понимает «ага», «конечно», «+»,
  «неа», «не интересно»; возраст принимает как `35`, `мне 35 лет`, `тридцать пять`.
  А вот неточные ответы («около 30», «чуть за сорок», «30-40») он переспросит.

## Хранение данных

**SQLite** (`database.enabled: true`) — таблица `candidates`. Колонки создаются
по шагам сценария: добавили шаг в конфиг — колонка добавится автоматически
(`ALTER TABLE`), старые записи сохранятся.

| Колонка | Описание |
|---------|----------|
| `user_id`, `username`, `first_name` | кто прошёл опрос |
| `status` | `completed`, `not_interested`, `rejected:<шаг>` |
| колонки по ключам шагов | `full_name`, `age`, `health`, `crime`, … |
| `answers_json` | все ответы одной строкой JSON |
| `created_at` | дата и время |

В базу попадают и отсеянные кандидаты (со статусом причины) — удобно для статистики.
В Google Sheets выгружаются только успешно прошедшие.

```bash
sqlite3 data/candidates.db "select created_at, full_name, age, status from candidates;"
```

## Логи

Формат: `время - имя - уровень - сообщение`. Пишутся в консоль и в файл
с ротацией (5 МБ × 5 файлов).

```yaml
logging:
  level: "INFO"          # DEBUG — подробнее, WARNING — только проблемы
  file: "logs/bot.log"   # null — только консоль
  log_steps: true        # логировать каждый шаг диалога
```

Логируются запуск и остановка, каждый шаг, отказы, ошибки отправки уведомлений
и выгрузки в таблицу.

## Продакшн

**systemd** (см. `deploy/tgbot.service`):

```bash
sudo cp deploy/tgbot.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now tgbot
journalctl -u tgbot -f
```

**Docker:**

```bash
docker build -t tgbot .
docker run -d --name tgbot --restart unless-stopped \
  -v $PWD/config.yaml:/app/config.yaml:ro \
  -v $PWD/credentials.json:/app/credentials.json:ro \
  -v $PWD/data:/app/data \
  --env-file .env tgbot
```

Бот работает в режиме long polling и сам переподключается при обрывах связи.
Состояния диалогов хранятся в памяти: после перезапуска процесса кандидату нужно
отправить `/start` заново. Если нужна непрерывность — подключается
`PicklePersistence` / Redis-хранилище python-telegram-bot.

**Безопасность:** токен и ключи только в `.env` / переменных окружения; `config.yaml`,
`.env`, `credentials.json`, `data/`, `logs/` перечислены в `.gitignore`. Встроен
лимит на частоту сообщений от одного пользователя (`rate_limit` в конфиге).

## Частые проблемы

| Симптом | Причина и решение |
|---------|-------------------|
| `Ошибка конфигурации: Не задан токен бота` | Нет `BOT_TOKEN` в `.env` и `bot.token` в конфиге |
| `Токен бота выглядит некорректно` | Токен должен быть вида `123456789:AA...` от @BotFather |
| `Сетевая ошибка при подключении к Telegram` | Нет доступа к API — укажите `PROXY_URL` |
| `Проверьте, работает ли прокси` | Прокси-сервер не запущен или указан неверный порт |
| `Не удалось отправить уведомление менеджеру: Chat not found` | Неверный `MANAGER_CHAT_ID`, либо менеджер не писал боту `/start`, либо бот не добавлен в группу |
| `Forbidden: bot can't initiate conversation with a user` | Менеджер должен первым написать боту `/start` |
| `manager_chat_id не задан` | Уведомления выключены — задайте `MANAGER_CHAT_ID` |
| В таблицу ничего не пишется | Запустите `python tools/preflight.py` — он назовёт причину |
| `Не удалось создать таблицу` | В Google Cloud не включены Sheets API и Drive API |
| `Файл ключа сервисного аккаунта не найден` | Положите JSON в папку проекта и запустите `python tools/configure.py` |
| `The caller does not have permission` | Таблице не открыт доступ для сервисного аккаунта (`python tools/create_sheet.py --whoami` покажет адрес) |
| Бот молчит на кнопки | Диалог завершён — отправьте `/start` |
